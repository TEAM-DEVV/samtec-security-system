03

The four lenses

every merge · every phase exit

The senior roles are wired into the repository, not left as advice. Each pull request and each phase exit is reviewed through all four lenses — by people with the checklist, and by Claude Code with the reviewer agents.

Lens 1 · ArchitectDoes it still fit the design?
  • Right module, no cross-module table writes
  • Contract updated before code
  • No new tool without a logged decision
  • Data invariants untouched or amended consciously
.claude/agents/architect-lens.md
Lens 2 · Senior devIs it built well?
  • Strict types, Zod at every boundary
  • Errors mapped, none swallowed
  • Payroll & detection logic tested to the pesewa
  • Safe migrations, explicit units in names
.claude/agents/senior-dev-lens.md
Lens 3 · Full-stackDoes the seam hold?
  • Generated API client only, no hand fetches
  • Mock handlers match the contract
  • Loading / empty / error states on every screen
  • UTC stored, Accra rendered
.claude/agents/fullstack-lens.md
Lens 4 · Security analystWhat would I attack?
  • Record-level access tested (guard A ≠ guard B)
  • Maker–checker unbypassable via raw API
  • No PII in logs; templates encrypted, never images
  • Supply chain: provenance, release age, install scripts
.claude/agents/security-lens.md

Phase exit gate: demo runs end-to-end · four checklists pass on the phase diff · CI green · docs still true · security findings fixed or accepted in writing. A phase without its gate is not done, it is abandoned.
First run, on the Phase 0 pull request: Architect and Security passed with notes; Senior dev and Full-stack required changes. Two blockers were caught before merge — a status page that could show an old “Connected” after a failed check, and a reset script that could wipe whichever database it pointed at. Both were fixed with tests that fail against the old code, along with every note: minimal public health check, logs free of personal data, row-level security on every table, and a same-site cookie design for sign-in.

05

Ground rules

Contract firstNo feature starts before its endpoint exists in the OpenAPI contract. The contract is the border between us.
Mock the hardwareThe whole system demos with zero devices connected. Real hardware is an adapter, never a dependency.
Money is integersPesewas only. Payroll runs snapshot inputs and lock forever; corrections are new lines, never edits.
Punches are append-onlyIdempotent ingest, device time and server time both kept, replays no-op. Ground truth is never updated in place.
Templates, not imagesBiometric templates encrypted at rest, consented at enrollment, retention per Ghana Act 843.
Every phase demoableA phase ends with a named demo or it did not end. Weekly 15-minute check-in names the next one.
